### 2. Schema Sync Strategy

#### 2.1 Manual Maintenance

- **Key point**: Schemas are currently hand-written. When an entity interface changes, the corresponding `.schema.json` must be updated.
- **Checklist to keep in sync**:
  1. Add/remove properties in `properties` object
  2. Update `required` array
  3. Update `enum` values if enum members change
  4. Update `type` / `format` if field types change (e.g., `Date` -> `string` with `date-time`)
- **Example**: Show a side-by-side diff-like snippet of `Debt` interface change vs `debt.schema.json` change
- **Reference files**: `src/entities/debt/debt.entity.ts`, `src/schemas/debt.schema.json`

#### 2.2 Automated Generation (Recommended Future Path)

- **Key point**: Mention that the project currently has zero runtime dependencies and no generation pipeline. Propose adding `typescript-json-schema` or `ts-json-schema-generator` as dev tools.
- **Tool recommendation**: `typescript-json-schema` (from `YousefED/typescript-json-schema`)
- **Proposed script** (to add to `package.json` in a future iteration):


- **Caveats**: Decimal/Date fields may need post-processing (TypeScript `Date` becomes `string` with `format: date-time`; `Decimal` becomes `string`)

#### 3.2 Dynamic Form Generation

- **Key point**: Use a JSON Schema-driven form library (e.g., `@jsonforms/angular` or a custom mapper) to generate `FormGroup` definitions from schema properties.
- **Code example**: Custom mapper using `ReactiveForms` + `FormBuilder` (realistic, no external heavy dependency):

  ```typescript
  import { FormBuilder, FormGroup, Validators } from '@angular/forms';
  import { schemas } from '@cobranza-apps/entities';

  const debtSchema = schemas.debt.debt;

  function buildFormFromSchema(schema: typeof debtSchema, fb: FormBuilder): FormGroup {
    const group: Record<string, unknown> = {};
    for (const [key, prop] of Object.entries(schema.properties)) {
      const validators = schema.required?.includes(key) ? [Validators.required] : [];
      if (prop.format === 'email') validators.push(Validators.email);
      group[key] = ['', validators];
    }
    return fb.group(group);
  }
  ```

- **Reference**: `docs/usage-angular.md` (Reactive Forms section)

#### 3.3 Runtime Validation with `ajv`

- **Key point**: Install `ajv` in the Angular project for client-side validation before submitting to the API
- **Code example**:

  ```typescript
  import Ajv from 'ajv';
  import { schemas } from '@cobranza-apps/entities';

  const ajv = new Ajv({ allErrors: true });
  const validate = ajv.compile(schemas.debt.debt);

  const isValid = validate(formPayload);
  if (!isValid) {
    console.error(validate.errors);
  }
  ```

### 5. Tools and Generation Methods

#### 5.1 Manual Editing

- **Key point**: Current state. Editors with JSON Schema support (VS Code validates Draft-07 automatically)
- **Tip**: Use `$schema` header for IDE autocomplete

#### 5.2 TypeScript-to-JSON-Schema Generators

- **Tool**: `typescript-json-schema`
  - Command: `npx typescript-json-schema tsconfig.json Debt --required --out src/schemas/debt.schema.json`
  - Pros: Zero config, works with interfaces
  - Cons: May emit `Date` as `string` without `format`; may not preserve enum names
- **Tool**: `ts-json-schema-generator`
  - Command: `npx ts-json-schema-generator --path tsconfig.json --type Debt --out src/schemas/debt.schema.json`
  - Pros: Better type alias resolution
  - Cons: Slightly more complex config
- **Post-generation cleanup**: Script to inject `format: 'uuid'` for UUID fields, `format: 'date-time'` for Date fields, and `enum` for enum-backed strings
- **What to keep brief**: Full npm package integration — only shell commands and one-line pros/cons

#### 5.3 Validation Libraries

- **Angular / Browser**: `ajv` (lightweight, Draft-07 compliant)
- **Node.js / NestJS**: `ajv` or `fast-json-stringify` (if serialization performance matters)
- **Testing**: `jest-json-schema` or `ajv` in test assertions
