## Overview

Create one `*.dto.ts` file per entity, placed alongside its entity file. Each DTO file exports three types:

1. `CreateXxxDto` — fields required for creation (omit `id`, all audit timestamps, and any system-managed fields).
2. `UpdateXxxDto` — `Partial<CreateXxxDto>` (all fields optional for updates).
3. `XxxResponse` — mirrors the full entity interface (extends the entity interface).

**TypeScript utility types used**:
- `Omit<>` to strip `id`, audit fields (`createdAt`, `updatedAt`), and system-managed fields.
- `Partial<>` to make update DTOs.
- `extends` for Response DTOs.
- `Pick<>` where subset responses are needed (not primary for this task, but noted).

**Real types** (`Date`, `number`, `Decimal`, `UUID`, enums) are used directly — `class-transformer` will handle serialization in the consuming apps.

**Clear JSDoc** on each exported type.

## Per-Entity DTO Specifications

### 1. Company (`src/entities/company/company.dto.ts`)

**Entity reference**: `Company` (no `BaseEntity` extension; has `createdAt`, `updatedAt`)

**Imports needed**:
```typescript
import type { Company } from './company.entity';
```

**DTO definitions**:
```typescript
/**
 * Fields required to create a new Company.
 * Omits system-generated `id`, `createdAt`, and `updatedAt`.
 */
export type CreateCompanyDto = Omit<Company, 'id' | 'createdAt' | 'updatedAt'>;

/**
 * Fields allowed when updating a Company.
 * All creation fields are optional.
 */
export type UpdateCompanyDto = Partial<CreateCompanyDto>;

/**
 * Full Company shape returned by the API.
 */
export interface CompanyResponse extends Company {}
```

## Special Cases & Edge Cases Summary

| Entity | Special Omit Fields | Reason |
|--------|-------------------|--------|
| User | `passwordHash`, `passwordUpdatedAt`, `lastLoginAt` | System-managed identity fields |
| Client | `updatedBy` | Audit metadata set by system |
| DebtSchedule | `deletedAt`, `deletedBy`, `lastGeneratedDate` | Soft-delete fields + derived system field |
| InvoiceTemplate | `deletedAt`, `deletedBy` | Soft-delete fields |
| ReceiptTemplate | `deletedAt`, `deletedBy` | Soft-delete fields |
| PaymentAttempt | `reviewedBy`, `reviewedAt`, `amount`, `currency` | Auto-filled / review system fields |
| BankStatement | `totalTransactions` | Derived during parsing |
| PaymentMatch | `matchedAt` | System-generated timestamp |
| Notification | `sentAt` | System-generated timestamp |
| ClientDebtSummary | `lastPaymentId`, `lastDebtId`, `lastPaymentDate`, `lastDebtDate` | Derived fields |

## Notes

- All DTOs use `type` aliases for `CreateXxxDto` and `UpdateXxxDto` because they are simple mapped types (`Omit`, `Partial`).
- All DTOs use `interface` for `XxxResponse` with `extends` to preserve the entity interface exactly.
- No external dependencies are added; DTOs are pure TypeScript mapped types.
- JSDoc comments are provided on each exported type to clarify usage for both backend and frontend consumers.
