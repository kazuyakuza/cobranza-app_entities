# DTO/Entity Field Origin Review — Broad DTO for Event-Driven Microservices

## Context

The library sits in an **event-driven microservice architecture** with a single `ms-db-gateway`. Lib DTOs are **inter-service contracts**, not frontend API contracts. Therefore `Create*Dto` must be **broad** — strip only `BaseEntity` audit fields (`id`, `createdAt`, `createdBy`, `updatedAt`, `updatedBy`, `deletedAt`, `deletedBy`). Any microservice may supply all other fields before sending to the DB gateway.

## Problem

The library's current `Create*Dto` type aliases correctly strip only `BaseEntity` audit fields. However, earlier review flagged many fields (`status`, `clientCode`, `debtCode`, `invoiceNumber`, `receiptNumber`, `taxIdHash`, `emailHash`, `contactHash`, `referenceHash`) as incorrect in the DTO. Under the broad-DTO philosophy these are all valid fields that an emitting microservice may supply. No change is needed to the `Omit<Entity, AuditFields>` pattern.

`docs/usage-nestjs.md` §3 silently ignores the lib alias (class does not `implements` it), so the alias is dead code and lib changes go unnoticed.

## Goal

1. **Revert** any DTO that currently omits more than audit fields back to `Omit<Entity, BaseAuditFields>` only.
2. **Update encrypted field types** so they accept `EncryptedValue | rawType | null`.
3. **Sync schemas** (`src/schemas/*.json`) to match.
4. **Update tests** to allow raw strings in encrypted fields.
5. **Document** the narrowing pattern in `docs/usage-nestjs.md` and align `README.md`.
6. Keep `Create*Dto` / `Update*Dto` for **all** entities, including summary/notification entities (microservices may request creation via DB gateway events).

## Origin Legend

Given the broad-DTO inter-service contract model:

| Mark | Meaning |
|------|---------|
| `S`  | **Server-set** by `ms-db-gateway` only — always stripped from `Create*Dto`. Only `BaseEntity` audit fields qualify. |
| `C`  | **Microservice may supply** — kept in the broad DTO. Any field a microservice may send before the DB gateway persists it. |

Common `BaseEntity` audit fields (`id`, `createdAt`, `createdBy`, `updatedAt`, `updatedBy`, `deletedAt`, `deletedBy`) are ALWAYS `S` and omitted from tables below. All other fields are `C`.

## Confirmed Decisions

1. **Architecture**: Event-driven microservices + `ms-db-gateway`. DTOs strip only `BaseEntity` audit fields. All other fields are fair game in the inter-service contract.

2. **Encrypted property types**: Each encrypted field accepts `EncryptedValue | <raw type> | null`. Some microservices receive the raw value upstream, encrypt it, then pass `EncryptedValue` downstream. Others may receive already-encrypted data. Optionality (`?:`) already covers `undefined`.

3. **Summary / Notification entities (`ClientDebtSummary`, `CompanyMonthlySummary`, `Notification`)**: Keep `Create*Dto` and `Update*Dto`. Microservices may listen to events and request the DB gateway to create/update these records.

4. **Status fields**: Microservices may set status. Do NOT classify as server-managed. Status is part of the broad DTO.

5. **Sequential codes (`debtCode`, `clientCode`, `invoiceNumber`, `receiptNumber`)**: Microservices may generate them. They stay in the broad DTO.

6. **Hash fields (`taxIdHash`, `emailHash`, `contactHash`, `referenceHash`)**: The microservice that receives the raw data may calculate the hash, then send encrypted + hashed data to the DB gateway. They are NOT purely server-derived; they stay in the broad DTO.

7. **Narrowing pattern for consuming microservices**: Consuming microservices (e.g. public API gateway) define their own narrowed alias:

   ```ts
   type ApiCreateDebtDto = Omit<CreateDebtDto, 'debtCode' | 'status'>;
   ```

   The validation class `implements ApiCreateDebtDto`. This is the pattern `docs/usage-nestjs.md` should demonstrate.

8. **What to change in the library**:
   - Revert any DTO that currently omits more than audit fields back to `Omit<Entity, BaseAuditFields>` only.
   - Update entity interfaces so encrypted fields accept `EncryptedValue | rawType | null`.
   - Sync schemas (`src/schemas/*.json`) to match.
   - Update tests to allow raw strings in encrypted fields.
   - Update `docs/usage-nestjs.md` to show the `implements Omit<CreateDebtDto, ...>` narrowing pattern and explain the event-driven microservice DTO philosophy.
   - Update `README.md` if it mentions DTO usage.
